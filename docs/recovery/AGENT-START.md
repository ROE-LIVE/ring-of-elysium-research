Номера задают один допустимый порядок с учётом зависимостей. **ID устойчив, номер привязан к версии плана**. При новой сортировке назвать и версию, и ID. Зависимости всегда имеют меньшие номера; research идёт в конце. `work_state`: baseline — существующая опора, ready — текущая задача, queued — последующая, external_blocked — нужен внешний материал, done — полностью проверенная задача. Поле `status` и проценты по-прежнему описывают достигнутые этапы, а не очередь исполнения.

Проверка доступных входов и сохранение поручения, без клиента/сервисов:

```bash
python -B tools/recovery_task.py --task 5 --preflight
python -B tools/recovery_task.py --task 5-6 --output research/builds/2022/recovery/handoff-005-006.md
```

Имя output должно быть новым; файл не перезаписывается. `--preflight` возвращает2 при MISSING,1 при ошибке самого плана;0 означает, что автоматическая часть проверки прошла. MANUAL-проверки остаются обязательными. Содержимое ключа не читается; SHA считается только для runtime EXE. Статическое поручение можно выдать и без всех первичных материалов; список отсутствующего нужен для продолжения на новом стенде.

Если инструмент запускается из снимка agents-context, нужны явные пути к CSV и полному рабочему дереву:

```bash
python -B /PATH/agents-context/snapshots/recovery-plan-20261008-v2/tools/recovery_task.py \
  --csv /PATH/agents-context/docs/recovery/mechanics-2022.csv \
```
