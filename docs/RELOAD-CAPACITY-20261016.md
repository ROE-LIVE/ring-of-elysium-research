## Причина по первичному коду

Native020 воспроизвёл Windows-дефект: Glock17/14, R→reload_noop без расхода, но переход в состояние перезарядки. Проверка `1412F59C4` сравнивает текущий магазин с первым U32 конфигурации, полученной через virtual+10. Для Glock аппаратная точка прочитала **current17/capacity2**, тогда как HUD gun+90 показывал17. Getter `140CD9BF0` возвращает embedded gun+58+7B8=gun+810; getter текущего clip `1401F73F0` читает embedded+38=gun+90.

Переход: `1412F58F0`→`140F0107C`→FSM `141333F80`→reload-state `140F25850`; отправка49C в `140F26339/33E`. Успешная49D с result0 в `140E91F10` лишь возвращается; ненулевой result уходит в общий error handler140F63720, поэтому прежний success/no-ACK не исправлял неверную вместимость.

В ITEM_DATA нашего peer оставалось значение2 из Citori: **ref-record+56 = ITEM_DATA+54**, BE32, до count/records обвесов. Изменение definition и отправка4A0 меняли оружие/HUD, но не этот параметр. Адресный delta с правильным Glock/тем же UID подтвердил native capacity17; это серверный пакет, не изменение памяти игры. Первые экспериментальные delta ошибочно сохранили Citori/выбор snowboard в исследовательском скрипте; они не считаются положительной проверкой. `capacity_delta.py` теперь проверяет definition20002.
