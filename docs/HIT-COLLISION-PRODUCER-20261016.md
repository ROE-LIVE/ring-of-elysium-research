# Источник части попадания в клиенте 2022

Исследован корневой `Europa_Client.exe`, x64 0.2.989.0, SHA256 `2dca9b1e122e21363e14eeeb2372598c773205a907ed8d2b2d54a7229ad6ba18`. Адреса ниже относятся только к нему. Native007–009 выполнены в независимом runtime под Proton; оригиналы не изменялись. Исходная серверная формула урона этим разбором не восстановлена.

## Подтверждённая цепочка

`140FC3F20 →140FC0CD0 →140FC09F0 →PhysX raycast →140FC14A0 →140FC54A0 →140FC4E20 →140FC4C80 →140D09590 →1412F8F20 →140F15FF0 →140F16750 →11DD`.

На входе `140FC3F20` аппаратный watch на result+0x24 поймал запись после MOVUPS по `140FC5553`, PC остановки `140FC5557`. Контроль конечности дал3, головы1; UID совпал с мишенью. Вызов `140FC4C80` через virtual+D8 по `140FC4D13`, return `140FC4D19`, передаёт результат в `140D09590`. Ранее известный return `140D095D6` относится этой функции. R8 передаётся в `1412F8F20` без изменения; part находится по +0x24, targetUID по +0x28.

`140FC54A0` копирует уже готовые данные, а не вычисляет номер части. Среди правил выбора пересечения есть исключение existing2/new1: existing не заменяется. Объявлять алгоритм «выбрать наименьший номер» нельзя. `140FC4C80` при flag+0x2A1 вычисляет отношение квадратов текущей и исходной скоростей; связь с authoritative damage ещё не установлена.

Первый контроль головы промахнулся; watch без снятия после возврата наблюдал повторное использование стека. Эти значения исключены из доказательств. Повтор с ограничением времени жизни watch возвратом `140FC4BC4` дал part1 в правильном результате.

## Физический объект и метаданные

Вызов virtual+0x2B0 по `140FC0BD1` попадает в `PhysX3_x64.dll`, RVA `0x599C0`. Native008: база `0x6FFFF68D0000`, версия DLL3.3.4.0, SHA256 `6f380ba47f2bd4c085dabdeeac18e1f361ceddfd4c620bb736dfb5657d0913a5`. DLL в runtime и оригинале совпадают.

В `140FC14A0`, PC `140FC14FD`, rawhit[0] указывает на actor, rawhit[8] — shape. Это проверено по методам типов самой DLL: actor vtable RVA1CCE70/метод4BCC0 возвращает `PxRigidDynamic`; shape vtable1CFA70/метод60880 — `PxShape`. Раскладка не перенесена предположительно из другой версии SDK.

Код читает actor+0x10/userData и копирует32байта в output+0x20. Поэтому userData+4 даёт part, +8 — targetUID. Native008 на нужной мишени показал flags1/part3. Материал отдельно извлекается из shape и номера грани: virtual+C0/D0 в `140FC154F/1564`, результат output+0x40.

## Значения частей

Инициализатор `140A1C0B0` связывает имена и числа:

| MBP_BODY | 2 | 140A1C1EF / 140A1C1FC |

`DATA/CONFIG/QSPHYSXCONFIG.XML:56–72`, SHA256 `b443aad731fad4990ad41dbe1d78503be94a881e44e9f66786891b4340b51679`, содержит15 соответствий: Head→1; Pelvis/Spine/Spine1/Neck→2; руки/ноги→3. Reflection `mBoneToPartMapping` устанавливает смещение +0x2B0 по PC `140A1FB03`. Применение каждой строки отдельно ещё не прослежено. Кандидат `1409DAAE0` с совпадающим +0x2B0 оказался конструктором другого контейнера и не является доказанным потребителем mapping.

Теперь part1/2/3 установлены и по первичным именам, и по клиентским попаданиям. Это позволяет правильно выбирать feedback головы, но не даёт исходных множителей урона, брони или серверного lag compensation. Поле11DD+83 по-прежнему `shooter_path_use_c`, не headshot.

## Материалы и дальнейшая проверка

Native009: выбранный снег вернул материал802, камень305. В `DATA/TABLE/QSPHYSMATERIALDESCTABLE.XML:22,46` им соответствуют Rock и Snow_Hard. Есть поля `mPenetrationModifier` и `mDamageLostPercent`; формулу их применения нельзя вывести только из названий.

Для одной грани камня прочитаны три индекса/вершины и позы actor/shape. Преобразование в world space дало отклонение точки PhysX от плоскости0,00477см, совпадение нормалей0,99999999. Полная карта/mesh не выгружалась. Разбор отдельной преграды: `research/builds/2022/recovery/043-gun06/20261016T0300-native-obstacle/`.

Первичные доказательства producer: `research/builds/2022/recovery/038-gun07/20261016T0130-collision-producer/`, включая scoped watch, enum refs, body-part-contract.json и DLL type checks. Для исходного расчёта урона нужен authoritative handler/provider либо исходная согласованная fire/hit/hurt трасса с известными оружием, частью тела, бронёй и дистанцией.
