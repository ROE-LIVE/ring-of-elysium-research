# Единый реестр игровых сигналов2022

Актуальная таблица: [signals-2022.csv](signals-2022.csv).
UTF-8 с BOM, разделитель `;`, окончания CRLF — для Excel и программного чтения.
В первой редакции96 строк:42 описанных protocol-сигнала,51 кандидат из
исходников нашего peer и3 административных действия. Это рабочий реестр,
а не полный список всех сообщений оригинальной игры.

## Идентификация и происхождение

Только корневой `Ring of Elysium-2022/Europa_Client.exe`, x64 0.2.989.0,
SHA256 `2dca9b1e122e21363e14eeeb2372598c773205a907ed8d2b2d54a7229ad6ba18`,
основная зимняя карта16010. Адреса VA для EXE с preferred base0x140000000;
при ASLR вычислять RVA=VA−base и применять к фактической базе модуля.
Данные V99/2018 и внешние OpcodeDump без установленного SHA сюда не импортированы.

Источником индекса служат текущие Python-модули peer/парсеров, а не новая
декомпиляция EXE. `source_refs` — путь и строка относительно ROE_SERVER,
`source_sha256` позволяет проверить версию файла. Соответствующие рабочие
модули также находятся в run_roe_2022; часть исследовательских tools существует
только в полном workspace. `evidence_refs` преимущественно указывает на
research-артефакты полного workspace; административные инструкции в docs
доступны и в agents-context/run_roe_2022. Отсутствующий материал нужно запросить,
а не считать прочитанным.

Имена protocol-строк описательные. Пустой native-адрес означает «не внесён»,
а не отсутствие обработчика. Ссылки на связанные механики — навигация,
не доказательство каждого поля сообщения. Wire-схемы описывают проверенную
ветку/fixture; альтернативные версии payload могут существовать.

Адресные цепочки: [MODULE-SIGNAL-MAP-20261013.md](MODULE-SIGNAL-MAP-20261013.md).
Поля `chain_refs`, `chain_status`, `state_target` связывают opcode с картой
модулей и записью состояния. Partial не означает непрерывную трассу сети:
821/1069 имеют адресные decoder/handler/state, но вход и dispatcher ещё открыты;
4A0 имеет decoder, его конечный nativeconsumer ещё не установлен.

## Как читать и использовать

* `SIG2022-OP-XXXX` — стабильныйID для числовой ссылки/opcode.
  `opcode_hex` и `opcode_dec` содержат одно число в разных представлениях.
* `verification=source_reference_only`: AST нашёл сравнение command или
  пару `(hex,payload)`. Это кандидат: слой/направление/семантика не установлены.
  Сравнение может принадлежать loaderfixture, не входящему сообщению.
* `reviewed_source`: схема/назначение адресно сверены с кодом/комментариями
  парсера. Нативную проверку конкретного сценария смотреть отдельно по evidence.
* `manual_mode=typed_action` — доступное административное действие нашего
  стенда; это не opcode и не обнаруженная оригинальная консоль.
* `direction=C2S` — запрос клиента. Его нельзя послать клиенту как команду S2C.
  Например выстрел11DA принимается peer, а магазин обновляется4A0.
* `state_handler_or_fixture` не означает готовую кнопку/CLI. Для динамической
  ручной команды нужен controller, регистрация сущностей/UID и актуальное
  состояние. Одно821 показывает объект, но не гарантирует разрешённый pickup.

Для доступных typed action запустить Windows-комплект с `-LiveControl`,
в примере CSV заменить RUN_DIR текущим каталогом runs и UNIQUE_ID новымID.
Команда добавляет запрос в очередь; применение подтверждается событием
`live_state_action` с нужнымID и `accepted/reason` в `game-endpoint/events.jsonl`.
Повтор того жеID не повторяет действие. Подробности:
[STATE-CONTROL-20261012.md](STATE-CONTROL-20261012.md).

Raw-очередь `live-commands.json` допускает wire-команды, но не создаёт
серверное состояние автоматически. Не превращать произвольный payload
в пример для пользователя до проверки guard/состояния/наблюдаемого результата.

## Поручение принимающему агенту

> Прочитай AGENTS.md, docs/SIGNALS-2022.md и docs/signals-2022.csv.
> Возьми строку по signal_id или отфильтруй mechanic_ids. Проверь SHA билда
> и источников. Установи слой, направление, структуру и условия обработки.
> Если нужны первичные файлы, которых нет в переданном контексте, перечисли их.
> Добавь типизированное действие с обновлением серверного состояния, если это
> нужно для механики. Проверь wire/UI/state раздельно, включая отрицательный
> случай, и сохрани адресный отчёт. Обнови строку, источники, ограничения,
> критерии плана и дату. Не запускай клиента/сервисы без разрешения текущего
> пользователя. Не объявляй candidate/native/Windows подтверждёнными по имени
> opcode или успешной постановке команды в очередь.

План механик остаётся в `docs/recovery/mechanics-2022.csv`; данный реестр
описывает интерфейсы, не заменяет очередь работ и не считает процент готовности.

## Обновление реестра

Из ROE_SERVER:

```bash
python -B tools/build_signals_registry_2022.py --output docs/signals-2022.csv
python -B -m unittest discover -s tests -p test_build_signals_registry_2022.py -v
```

Генератор не исполняет модули, не читает ключи/трафик и не запускает игру.
Описание42 рассмотренных сигналов хранится в REVIEWED генератора. Новое
описание следует добавлять туда после адресной проверки; иначе повторная
генерация перезапишет ручную правку CSV. Новые административные действия
добавлять вместе с реальной реализацией и подтверждением, не только строкой.
После изменения копировать CSV/инструкцию в agents-context и сверять SHA.
