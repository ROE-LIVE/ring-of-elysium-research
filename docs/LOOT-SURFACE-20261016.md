# Высоты тестового лута — 16.10.2026

Только корневой2022 x64, Iceland16010. Источник высот и параметры — [TERRAIN-HEIGHTFIELD](TERRAIN-HEIGHTFIELD-20261016.md). Билд и адреса других версий не используются.

В старом `windows-smoke-20261015.json` все8предметов имели Z259109. Read-only reader исходного Linux PXBIN показал разный рельеф: M4 всего+0,05см относительно terrain, AK−8,50см,5.56+3,79см,7.62−4,76см,9мм+6,99см,12ga−1,55см,шлем−12,24см,жилет−18,64см. Четыре точки ниже поверхности более чем на2см. Это подтверждённая ошибка тестовой расстановки, **но она не объясняет полное отсутствие M4**: её исходный Z практически совпадает с поверхностью.

Для этих восьми открытых точек подготовлен диагностический вариант `ceil(terrain_z+2см)`, без изменения XY/UID/index/quantity и без правки исходной карты точек. Это не исходный генератор, не правило для этажей/мебели и не учёт размеров/ориентации каждой модели. Аудит до/после сохранён CSV; после нет root-position ниже terrain. Не применять такой перенос ко всему каталогу: предметы на верхних этажах должны оставаться там.

Native022 загрузил8предметов у позиции игрока365100/544000/259107. Обычными UI drag приняты M4190500/AK190501 в slots2/3, правым кликом обе пачки190502/190503, жилет190507 и шлем190506. Поле `catalog_visibility` подтверждает все8индексов и их удаление после pickup. Это Proton, не новый Windows-повтор.

`tools/audit_loot_surface_2022.py` делает только проверку и новый CSV, без записи во входы. Высота над terrain помечается как возможная статическая поверхность, не как автоматически плохая точка. Нужен собственный извлечённый PXBIN с проверенным SHA; ресурс не включается в Git.

Экспорт теперь сохраняет `loot_catalog_ready/probe`, spawned/removed indexes, позицию и пределы каталога. Launcher записывает SHA/число предметов/радиус/границы уже проверенного снимка. Даже первый poll вне радиуса даёт один пустой диагностический event; последующие неизменные poll не засоряют журнал. Raw/AUTH/путь каталога не экспортируются.
