# HP06: автомат жизни и граница down/revive, билд 2022

Состояние: 12.10.2026 01:12 UTC. EXE 0.2.989.0 x64, карта 16010, SHA-256 `2dca9b1e122e21363e14eeeb2372598c773205a907ed8d2b2d54a7229ad6ba18`. Контракт оживления пока не установлен.

## Первичные факты

В независимом Proton-клиенте 262 найден встроенный компонент `engine+0x2C0`: определение по +0, текущий объект состояния по +8, его номер по +0x28. Конструктор `0x14122F530` регистрирует `Alive=0`, `Dead=1`, `BadlyWounded=2`; буквальные имена находятся по `0x1427CD040`, `0x14277A84C`, `0x1427CD030`. Источники: life-state-names-262.json, life-component-262.json и адресные ASM.

Обработчик `0x533` — `0x140D69550`. Он пишет life-cache+0x5EA=0xDC по `0x140D695E1`, для своего игрока устанавливает world+0x21, принудительно выбирает состояние 1 и вызывает `0x14122F490` по `0x140D69722`. Пакет `>IQ` длиной 12 байт с собственным UID перевёл клиента 262 в Dead; нажатие W на 0,5 секунды не изменило XYZ. Прямой диагностический пакет не меняет Python WorldState, поэтому этот опыт не подтверждает серверную транзакцию смерти.

Декодер `0xDA3` — `0x140C2D0F0`: count ограничен 16, union выбирается через `0x140C2CDE0`, шаг распакованной записи 0xF05. Проверен частный wire-вариант `>QBBBB`: UID, count=1, непрозрачный байт=1, selector=4, value. Обработчик `0x140D69D60` по `0x140D6A03E` записывает byte(value−0x25) в cache+0x5EA: 0/1/2 дают 219/220/221. Это **не номера состояний автомата жизни**. Адресная остановка подтвердила вход и запись.

Свежий клиент 265 после DA3 value=2 оставался Alive=0, forcedID=0, хотя кэш равнялся 221. Наблюдение чтений одного байта кэша в течение 8 секунд не дало срабатываний; это ограниченное окно, а не отсутствие всех потребителей. Scene callback `0xDCF`, `0x140D668F0`, по `0x140D66BDD` задаёт Alive=0. Его связь с отрицательным down-результатом — гипотеза.

Ресурс `DATA/TABLE/EURO/QSINTERACTCONFIGTABLE.XML`: type 5, строка 195 — взаимодействие с игроком на 225 см; type 15, строка 627 — revive-device на 400 см; фильтры содержат `EuFsmAlive::BadlyWounded` и `EXTRA_STATE_REVIVE`. SELF KILL/HINT Lua различают down и death: `SELFKILLHINTPANELLOGIC.LUA:53`, `GAMEHINTCFG.LUA:216`. Источники, SFC-смещения и SHA выбранных XML/Lua сохранены в table-candidates.json и lua-*-hits.json. Наличие механизма не устанавливает правила зимнего Training или squad.

## Отрицательные результаты и ограничения

В клиенте 262 DA3 value=2, value=1 и value=2 с HP=0 через 1069 не включили BadlyWounded: W давал 235–238 см движения, выстрел расходовал патрон. HP=0 отдельно не равен смерти. DA3 selector=15 вызывает виртуальный actor+0x278 по `0x140D6A1EB`; таблица собственного класса `0x14276D178` ведёт в пустую функцию `0x14019B8F0`.

619 также пустой; 688/691 и 535/537/53D отсутствуют в двух проверенных callback-таблицах этого EXE. Список коллеги для неопределённого билда — подсказка названий. В primary-таблице функция лежит в node+0x18, имя в node+8; в secondary функция в node+8. Ранние неверные чтения primary и встроенного компонента исправлены.

Клиент 264 не достиг сцены из-за пересечения с завершением 262 в том же Proton-prefix; протокольным отрицательным результатом он не считается. Свежий 265 достиг сцены. Запуски 262–265 завершены; выбранные EXE и две DLL независимых копий после опыта совпадают с оригиналами (selected-hashes-before/after.json в каталогах запусков).
