`COLDDAMAGETABLE.XML:4–12`: **температура тела = погода + ветер с учётом помещения + огонь**, единица0.01°C, полный HP1000. Positive iDamage вычитает HP. При−25°C строка задаёт50,−35°C75,−45°C100; от−15°C и выше0. `COLDPOWERTABLE.XML`: отдельный запас морозостойкости1000; при−25°C изменение−50, при+5°C+5, при+10°C+10. Знаки противоположны HP. Это не buff915150HP/с из ZONE06; совместное применение без исходной политики может удвоить урон.

`OUTSIDETEMPETABLE.XML`: только **map16011**,14 точек0..1440с. Комментарий задаёт линейную интерполяцию погодной/ветровой температур и начало после выбора клетки. После удаления недопустимых spreadsheet-атрибутов XML всё равно некорректен: открывается vecOutSideTempePoint, закрывается vecDrawGroups, строка32. Точки сохранены как текстовые наблюдения, не как доказательство runtime-загрузки. Исходник не исправлялся. Перенос на16010 не обоснован.

HUD обычной карты `WEATHERNOTIFYPANEL_ICELOGIC.LUA:74/78` читает ATR_TEMPERATURE и math.ceil(raw/100). Ночной `ICELANDNIGHT/GAMETIMEPANEL/GAMETIMEPANELLOGIC.LUA:57/80` читает **ATR_BODY_TEMPERATURE**, не тот же атрибут. `UICOLDBARCONFIG.LUA:13` читает UIGetColdRatio. Не смешивать погоду, температуру тела, морозостойкость и урон закрытой зоны.

## Что отсутствует

GenericStartInstanceTempe из исходного callback известен только по прежней stub-трассе. В распакованных DATA/SCRIPT uppercase LUA и SERVER XML исполняемый provider не обнаружен. Не установлены: момент warning/normal переключения, область действия по region, начальная температура/сброс на стадиях, скорость тиков, интерполяция ColdDamage/ColdPower, indoor/fire/wind binding и условие прикрепления урона. Поэтому готовый физический расчёт не внедрялся; существующие10D0 и buff915 остаются отдельными проверенными сигналами.

Следующий опыт для исходной кривой: **sanitized authoritative trace map16010** с UNIX/elapsed, stage/region, ATR_TEMPERATURE/ATR_BODY_TEMPERATURE/cold reserve/HP, входом и выходом из alert/frozen/помещения либо исполняемый GenericStartInstanceTempe/BT_SHRINK_RANGE_SELECT provider. Нужны значения до и после перехода, а не один скриншот термометра. Ночная таблица16011 этого пробела не закрывает.
