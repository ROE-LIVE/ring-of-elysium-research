## Что установлено и что является моделью

Первичные LayoutManager+76prefab дают `world = position + rotation × (scale × local)`. Независимо сверены7155/7155узлов из ранее полученного списка; теперь они перечисляются непосредственно из клиента без этого списка. [Манифест81ресурса](config/prefab-loot-sources.json) хранит архив/диапазон/размер/SHA:76prefab+LayoutManager+4таблицы. Legacy-ресурс отдельно: Common.sfc, LZ4 payload11043324, raw5317283байт, SHA2187235d…; описание [здесь](config/legacy-resource-source.json). Размер packed лежит за4байта до payload.

**Не восстановлены:** исходный RNG/seed, смысл iCount как веса либо квоты, binding Controller/TypeId→LootControl, специальные51/52, все поверхности и серверный provider GenericStartLoot. Наличие XML не означает наличие исполняемого host. Scalar/array приоритетных групп расходятся; в обычной item-таблице нет соответствующих пулов51/52.

Текущий генератор — явная **H1**:

1. Выбрать контроллеры1/3/5; упорядочить узлы по Index.
2. Отдельный `random.Random(seed*16+controller)` для каждой группы.
3. `num_percent_array` трактуется как вероятность1..Nпредметов; остаток до100 — пустая точка. Это гипотеза.
4. `iCount` используется как вес с возвращением; неподдержанные ID исключаются, веса перенормируются. H2 с конечными квотами сохранена в общем генераторе, но не используется текущим SourceLoot.
5. Дополнительные стопки выбираются прежней `extra_bundle`; не все семейства специальных/Extra2-полей реализованы. Их исходные значения присутствуют в данных.
6. В prefab-режиме radius и bundle_spacing принудительно0: исходныйXYZ не меняется. Несколько предметов могут совпадать геометрически. Нет гарантии предмета в каждом доме.

**7155узлов ≠7155предметов**. Seed20261019 даёт8008предметов;20261020 —8083. В квартале413000..419000/554000..560000:15узлов, соответственно8/17предметов. Смена порядка входных узлов результата не меняет. Числа и канонические SHA записаны в [проверках](evidence/current-generation-checks.json); это результаты нашего H1, не записи оригинальных матчей.

## Сгенерировать каталог без клиента

Python3.11+; для этой команды сторонних зависимостей нет. Из этого каталога:

```bash
python -B tools/generate_catalog.py --seed 20261019 --output generated-full.json
python -B tools/generate_catalog.py --seed 20261020 --bounds-cm 413000 554000 419000 560000 --output generated-quarter.json
```

Файл должен быть новым; повтор не перезаписывает его. `generated-*` игнорируются Git. Каталог — JSON для анализа/совместимого peer, команда сама игру не запускает. Совместимость со всеми ревизиями публичного launcher не заявляется; поддержка78ID привязана к нашему снимку кода687456b.

## Независимо получить данные из своего клиента

Нужен полный2022клиент с тем же EXE и ресурсами. .NET, Proton, ключи и сервер не требуются. Установить зависимость адресного SFC-reader, затем указать **новые, отдельные** каталоги:

```bash
python -m pip install -r requirements.txt
python -B tools/export_source_from_client.py --client /path/to/client2022 --cache /tmp/roe-loot-cache --output /tmp/roe-loot-data
```

В PowerShell можно указать `--client "G:\REsearch\Ring of Elysium-2022"` и два новых каталога вне клиента. Читаются81выбранный ресурс и один legacy-блок, SHA обязателен. В cache остаются XML только вашей локальной копии; **не добавлять cache в Git**. Выход — CSV/JSON, никаких изменений клиента. Повтор в существующие каталоги намеренно отклоняется.

В текущем workspace эта команда повторена из независимого runtime-клиента: `prefab-nodes.csv`, `legacy-entitypoints.csv`, `loot-tables.json` совпали с опубликованными **побайтно**. Проверено Python3.13/lz4 4.4.5; [результат](evidence/source-reproduction-checks.json).

```bash
python -B -m unittest discover -s tests -v
```

31проверка: преобразования координат, исходные пресеты, RNG/квоты, несовпавшие SHA/диапазоны, полное воспроизведение двух каталогов, неизменность источника и запрет пересечения output/cache с клиентом.

## Как связано с игровым peer

`SeededScenarioFactory` создаёт план при новом входе в комнату; handoff сохраняет существующий объект/seed и подобранные предметы. `load_source→build→LootCatalog.validate_fixture→match_loot_catalog` связывает источник и backend. Нынешние index начинаются с2000000, entityUID — с0x31d0900000000: это наши пространства ID. AOI2000см/visible128/batch16 и pickup registry — наша политика.

[reference-source](reference-source) содержит наши актуальные части интеграции/AOI/shared/corpse/airdrop для чтения; это не самостоятельный сервер. Две tool-копии адаптированы только для изоляции списка поддержанныхID от большого weapon-module; полные исходные версии сохранены рядом, source SHA — в [provenance](evidence/source-provenance.json).

Native012 подтвердил обычный вход в один дом, семь pickup, MPX19/85 и R8704/15, затем20сUDP/handoff без возврата подобранного. Это подтверждение цепочки для одного участка, **не проверки всех8008предметов/этажей**. Старые неудачные маршруты010/011 не заменяются этим успехом. [Сводка](evidence/native012-source-loot-summary.json), [подробности](../../docs/NIGHT-20261018-19-LOOT.md).

Для продолжения: LOOT01/LOOT02/LOOT03/LOOT05/LOOT09/LOOT11 и полный [индекс материалов](evidence/material-index.csv).
